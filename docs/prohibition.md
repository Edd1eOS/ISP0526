# 红线清单（Prohibition）

> 本文件列出**绝对不允许**的行为。违反任何一条 = PR 拒绝合并 / 代码立即回滚。
> 适用于：人类开发者、AI 协作工具（Copilot / Cursor 等）、第三方贡献者。

---

## A. AI 输出安全（最高优先级）

1. **禁止 LLM 生成事实**：所有院校信息、学费、申请要求、奖学金等必须来源于 `packages/core/data/*.json` 或受信任 API 响应，LLM 仅做翻译 / 润色 / 重排。
2. **禁止输出无 source_id 的推荐结论**：每条推荐必须可追溯到具体数据条目。
3. **禁止 LLM 直接控制业务决策**：录取概率 / 评分 / 排序由规则引擎产出，LLM 不得改写数值。
4. **禁止 Prompt 注入未净化的用户输入**：用户文本进入 prompt 前必须经过白名单字段抽取（Zod schema）。
5. **禁止跳过 5 层防护**：见 spec.md 第 4 章，任何一层缺失都视为违反。

---

## B. 合规与法律

6. **禁止收集中国未成年人个人信息无监护人同意流程**（PIPL）。
7. **禁止跨境传输用户数据未声明**：所有数据流向（Supabase Sydney / Vercel Edge / 第三方 LLM）必须在隐私政策列明。
8. **禁止使用未授权品牌资源**：QS / THE / US News 排名 logo、院校 logo、MBTI 商标。本项目用 Big Five (TIPI) 替代 MBTI。
9. **禁止给出"录取保证"措辞**：所有推荐文案必须包含不确定性提示（见 `legal/DISCLAIMER.md`）。
10. **禁止冒充人工顾问**：AI 输出必须明确标注为 AI 生成。

---

## C. 商业行为

11. **禁止销售压迫话术**：推荐报告不得诱导用户立即联系中介。
12. **禁止隐藏 B2B 抽成**：中介推介必须显示利益声明（"我们从此中介获得返佣"）。
13. **禁止 dark pattern**：默认不勾选订阅、明显的关闭按钮、无诱导性默认。

---

## D. 代码工程

14. **禁止 Chinese 注释 / docstring / 标识符**：所有代码（含注释）必须英文。
15. **禁止 emoji**：代码、commit、PR 描述、项目内 markdown 一律无 emoji（仅人对人聊天可用）。
16. **禁止提交密钥 / token**：`.env*` 一律 git-ignore；CI 通过 GitHub Secrets 注入；如不慎提交立即撤销并改写历史。
17. **禁止 `any` 滥用**：TypeScript strict mode；`any` 必须配合 `// reason: <why>` 注释，且 PR Review 重点关注。
18. **禁止跳过 lint / typecheck**：`--no-verify` 推送、`eslint-disable` 整文件、`@ts-ignore` 无原因——一律拒绝。
19. **禁止未测试的业务逻辑合并**：规则引擎、AI 适配层、评分核心覆盖率 ≥ 80%。
20. **禁止新增非必要实体**：如无必要勿增实体，保持工程可扩展和可维护。

---

## E. 仓库与基础设施

21. **禁止直接推送 `main`**：所有变更必须经 PR。
22. **禁止 force push 共享分支**：`main` 及任何团队分支。
23. **禁止删除 production 数据库** / **跳过备份操作**：参考 user_coding_standards.md 第 6 条（Terminal 安全：不在终端跑文件删除命令）。
24. **禁止在生产环境用 service_role / sb_secret_ key 暴露给前端**：仅服务端使用。
25. **禁止把开发计划 / 个人 TODO 提交到项目 docs**：项目目录文档必须对评审人 / 客户友好。

---

## F. 范围控制

26. **禁止偏离 spec.md**：未在 spec 中描述的功能不得实现；若需新增，先改 spec 再写代码。
27. **禁止过度工程化**：单次使用的逻辑不抽象成包；不预留"未来可能用到"的接口。
