## 1. 产品愿景与定位

### 1.1 一句话定义
**用客观化、个性化、低压力的 AI 诊断，替代留学中介前置咨询环节，让学生在零压力中获得可信任的留学方案。**

### 1.2 核心价值主张

| 维度 | 传统中介 | ISP0526 |
|---|---|---|
| 信息来源 | 顾问个人经验 + 利益偏向 | 公开数据 + 可解释规则引擎 |
| 沟通压力 | 销售导向、催签约 | 自助测评、AI 翻译规则结论 |
| 个性化 | 套模板 | 多维度评分模型 |
| 价格 | 5,000-30,000 RMB | C 端免费，人工跟进可选 |
| 时间成本 | 多轮人工沟通 | 15-30 分钟一站式 + 可选人工 |

### 1.3 商业模型（人工层中转）

- **C 端（用户面）**：免费完整诊断 → 输出报告 → 报告底部低调入口「想找人聊聊？」→ 用户加我们团队 WhatsApp / WeChat。**用户全程不直接接触任何商业中介。**
- **运营层（团队内部）**：我们在 WhatsApp / WeChat 对话中：
  1. 听用户讲实际诉求；
  2. 若能直接解答（基础问题），免费回答，沉淀信任；
  3. 若涉及签约 / 文书 / 签证等深度服务，匹配后台合作中介，由我们引荐。
- **变现**：合作中介按 **CPL（每条引荐线索）+ 后端成功签单分成** 结算。费率与中介一对一议定，对用户不可见。
- **流量**：自媒体引流（小红书 / 抖音 / B站 / 微信公众号），每渠道独立 UTM 链接。

**与传统中介的核心区别**：我们是用户与中介之间的人工质量层；用户从未被"扔给"销售导向的中介，整个体验对用户呈现为"和一个独立的留学顾问团队对话"。

## 2. 范围（Scope）

### 2.1 Phase 1 包含
1. 多模态学生背景输入（表单 + 对话 + 简历 + 语音）
2. 三层心理学/偏好评测（人格 / 学习偏好 / 生活偏好）
3. 加权多维匹配引擎（规则优先，LLM 仅语言层）
4. 三档推荐报告（冲刺 / 匹配 / 保底）
5. 报告输出三件套（网页 / PDF / 微信长图卡片）
6. 报告 ID 生成（六位码，团队 admin 后台凭此调取用户完整方案）
7. 用户账号系统（保存方案 / 偏好）
8. 中英双语 i18n
9. PostHog 漏斗分析
10. 基础合规（中国 PIPL + 澳洲 Privacy Act）

### 2.2 Phase 1 **明确不包含**（防止 scope creep）

- 任何付费功能 / 支付集成
- 移动端原生 App
- 中介自助登录后台（Phase 1 内部人工运营）
- 舍友匹配 / 办卡 / 租房 / 学业准备任务系统（Phase 2+）
- 实时聊天 / 客服系统
- ML 模型训练（数据沉淀后 Phase 2 启动）
- GDPR 合规（EU 用户非目标市场）
- 第三方排名 API 付费集成（仅用公开数据 + 人工 curate）

## 3. 用户角色

### 3.1 主用户：**学生**（C 端）
- **画像 A — 探索期**：高二 / 大二，对留学有意向但目标模糊
- **画像 B — 决策期**：高三 / 大四，已有部分目标但需验证
- **画像 C — 焦虑型**：被中介轰炸过、对销售反感、寻求客观信息

### 3.2 次用户：**合作中介**（B2B，对用户不可见）
- Phase 1 仅通过微信 / 邮件对接，**无登录系统、不出现在任何用户面 UI**
- 运营团队据用户的报告 ID 在内部 admin 调取方案，再人工引荐至合适中介

### 3.3 运营者：**我们团队**（2-3 人）
- 直接在 WhatsApp / WeChat 接待用户，承担人工质量层职责
- 通过内部 admin 页：按报告 ID 查方案、导出 leads、人工分发给中介、跟踪状态

## 4. 用户旅程（User Journey）

```
[自媒体引流]
   ↓ 点击带 UTM 的链接
[Landing Page] ── 中英切换 ── 隐私 Banner（PIPL 合规）
   ↓ "开始免费诊断"
[Step 0: 留学阶段选择]  ← 本科 / 硕士（Phase 1 仅这两个）
   ↓
[Step 1: 学术背景输入]  ← 多模态四选其一
   ├─ 表单填写（默认，最快）
   ├─ 对话式问答（适合"我不知道要填什么"型用户）
   ├─ 简历/成绩单上传（PDF / 截图 → OCR）
   └─ 语音输入（移动端友好，"说一下你的成绩和背景"）
   ↓
[Step 2: 偏好与目标]  ← 渐进式问卷（不超过 3 屏）
   ├─ 目标国家/地区（可多选、可"还没想好"）
   ├─ 专业方向（多选 + "未确定"选项）
   ├─ 预算范围（拖动条 + "暂不考虑预算"）
   └─ 时间线（明年秋 / 后年春 / 灵活）
   ↓
[Step 3: 三层评测]  ← 15 题，1.5 分钟
   ├─ Big Five 人格（TIPI 10 题）
   ├─ 学习偏好（5 题）
   └─ 生活偏好（5 题）
   ↓
[Loading 页]  ← "AI 正在为你匹配 200+ 全球顶尖项目"（含进度条与可读性提示）
   ↓
[报告页]  ← 网页版（默认展示）
   ├─ 个性化诊断摘要（LLM 生成，基于规则结论翻译）
   ├─ 三档推荐：冲刺 5 / 匹配 5-10 / 保底 5
   ├─ 每条推荐：院校 + 项目 + 评分（含分项）+ 推荐理由（带数据引用）
   ├─ 综合花费估算（学费 + 生活费 + 年限）
   ├─ "下载 PDF" / "生成微信长图" / "分享链接" 按钮
   └─ 底部柔和卡片：「想找人聊聊？」（surface 色，非主 CTA 渐变）
   ↓ 点击卡片
[联系我们页]
   ├─ 一句温和说明：报告里任何想深入聊的地方，可以加我们
   ├─ WhatsApp 链接 + WeChat 二维码
   ├─ 报告 ID（六位码，告诉团队这个就能调出你的完整方案）
   └─ "保存方案到我的账户"（若未登录则提示注册）
```

**关键设计原则**：
- 每一步退出可继续：用户离开后下次回来从断点继续
- 全程进度条可见，但不显示"还剩 X 题"以降低压力
- 任何步骤都可"跳过 / 之后再说"，对应字段在匹配引擎中按"未知"处理（用默认值而非剔除候选）

## 5. 功能需求（Functional Requirements）

### FR-1 多模态输入

| ID | 描述 | 验收标准 |
|---|---|---|
| FR-1.1 | 表单输入 | 渐进披露，单屏不超过 5 字段，含字段级帮助文案 |
| FR-1.2 | 对话式输入 | LLM 引导问答，每轮一个问题，可回退修改 |
| FR-1.3 | 简历/成绩单上传 | 支持 PDF / PNG / JPG，单文件 ≤ 10MB；文本 PDF 用 pdfjs，图像用 GPT-4o-mini Vision；OCR 后用户可校对再确认 |
| FR-1.4 | 语音输入 | Web Speech API 默认（免费），中文识别置信度 < 0.7 时切 Whisper API；**原始音频永不落库**，转写文本可落库（用户可删除） |
| FR-1.5 | 多模态结果统一 | 所有输入最终归一为同一 `StudentProfile` Schema（Zod 校验） |

### FR-2 三层评测

| ID | 描述 | 验收标准 |
|---|---|---|
| FR-2.1 | Big Five (TIPI) | 10 题，5 维度（O/C/E/A/N）各 0-7 分 |
| FR-2.2 | 学习偏好（5 题） | 班级规模、教学风格、理论 vs 应用、独立 vs 协作、节奏 |
| FR-2.3 | 生活偏好（5 题） | 城市规模、气候、华人社区密度、安全感需求、社交活跃度 |
| FR-2.4 | （隐藏）职业倾向（嵌入偏好步） | 移民倾向、回国就业、实习重要性、薪资敏感度 |
| FR-2.5 | 题面措辞低压力 | 无对错选项，使用 Likert 5 级，措辞中性 |

### FR-3 数据集

| ID | 描述 | 验收标准 |
|---|---|---|
| FR-3.1 | 院校规模 | Phase 1 覆盖 ≥ 200 所院校：澳洲全量（~40）+ 美/英/加/新 Top 50 + 港新 + niche 特色校 |
| FR-3.2 | 项目颗粒度 | 数据精确到具体 program（如 `UNSW Master of IT`），含 GPA 门槛、语言门槛、学费、学制、专业领域 |
| FR-3.3 | 标签体系 | 每项目挂多个标签：领域顶尖 / 性价比 / 跳板型 / 移民友好 / 学费友好 / 奖学金 / 华人友好 / 特定职业出口 |
| FR-3.4 | 数据来源 | 仅公开数据 + 人工 curate，每条记录含 `source_url` + `last_verified_date` |
| FR-3.5 | 更新机制 | Phase 1 数据存仓库 `packages/core/data/`，PR 评审更新；每季度全量复核 |

### FR-4 匹配引擎（核心 — 加权评分，非过滤器）

**硬门槛（仅剔除"完全不可能"的候选）**：
- 学术门槛：GPA 低于 program min × 0.85（留 15% 容差，保留"冲刺"可能）
- 用户硬性排除：明确"不去某国家"
- 申请阶段错配：本科 vs 硕士不混

**软评分（多维加权，不剔除，仅排序）**：

```
final_score (0-100) =
    0.30 * academic_fit    # GPA + 标化超出门槛的余量
  + 0.15 * personality_fit # Big Five → 教学风格距离
  + 0.15 * lifestyle_fit   # 城市/气候/华人社区 等
  + 0.15 * career_fit      # 行业出口/实习/移民/就业地
  + 0.10 * budget_fit      # 总花费 vs 预算
  + 0.10 * tag_boost       # 用户勾选/暗示的特色标签
  + 0.05 * reputation      # 综合排名 normalized
```

**权重个性化**：
- 默认权重如上
- 用户在偏好步骤的回答会**动态调整权重**（如选"预算非常紧张" → `budget_fit` 权重从 0.10 升到 0.20，其他按比例缩放）
- 权重调整逻辑必须有规则代码实现，**不允许 LLM 决定权重**

**输出三档**：
- 冲刺（Stretch）：academic_fit 落在 [40, 65] 的 top 5
- 匹配（Match）：academic_fit 落在 [65, 90] 的 top 5-10
- 保底（Safety）：academic_fit 落在 [90, 100] 的 top 5

**可解释性要求**：
- 每条推荐**必须**附带分项得分 + 至少 3 条文字理由
- 每条理由**必须**引用至少 1 个数据源（`source_url` 或规则 ID）
- LLM 仅做"把规则结论翻译成自然语言"的工作，**禁止补充任何院校事实**

## 6. 非功能需求（Non-Functional Requirements）

### NFR-1 性能
- LCP（首屏内容渲染）< 2.5s（4G 网络）
- 诊断报告生成（含 LLM 调用）< 15s，超时降级为"我们已收到，1 分钟内邮件送达"
- 简历 OCR < 8s
- 语音转写实时 streaming（Web Speech）

### NFR-2 可访问性
- WCAG 2.1 AA 基础合规
- 全键盘可操作
- 暖色调高对比度（对比度 ≥ 4.5:1）

### NFR-3 安全
- 所有 API Route 经 Zod 校验
- Supabase RLS 全表启用
- 简历文件存 Supabase Storage 私有 bucket，签名 URL 临时访问
- 速率限制：未登录用户 IP 维度 30 次/小时，OCR 与 LLM 接口单独限流
- LLM 输出**必须**经 post-filter 校验（schema + 白名单），失败不展示

### NFR-4 隐私与合规
- **落库数据**：用户基本信息、测评结果、简历文本（不存原图超 90 天）、报告
- **永不落库**：原始语音、原始截图未经用户确认前的临时数据
- **删除权**：账号删除 → 30 天硬删除（保留 30 天用于法律/争议）
- **合规适用**：中国 PIPL + 澳洲 Privacy Act 1988；不主动针对欧盟用户
- **隐私政策 + 服务条款**：`legal/PRIVACY.md` + `legal/TERMS.md`，多语言版本

### NFR-5 反 AI 幻觉硬约束
1. **匹配结论不来自 LLM**：100% 来自规则引擎
2. **LLM 仅做翻译**：把规则结论转为自然语言报告
3. **每条事实必须可追溯**：院校信息 → 数据集行 ID；建议 → 规则 ID
4. **Post-filter 校验**：LLM 输出经 Zod schema + 实体白名单 + 数字范围校验；不通过则重试或降级到模板化输出
5. **拒答机制**：用户问超出规则可回答范围的问题（如"我能拿全奖吗"）→ 明确告知"这需要个性化评估，可以加我们团队聊聊"
6. **审计日志**：每次 LLM 调用记录 prompt / response / 校验结果

### NFR-6 可观测性
- Sentry 错误追踪
- PostHog 产品分析
- LLM 调用日志独立存储（Supabase 表 `llm_audit`）
- 每周自动汇总：转化漏斗 + 错误率 + LLM 失败率

## 7. UI/UX 设计原则

### 7.1 视觉系统总纲
- **设计语言**：**Warm Claymorphism**（暖色调黏土质感）
- **理由**：低压力 + 可亲 + 适配 Phase 2 游戏化迁移；区分于传统留学中介的"商务严肃"视觉
- **参考来源**：Meng To 的 Claymorphism UI（结构）+ 自定义暖色 palette（视觉）

### 7.2 设计 Token（单一事实源）
所有界面只能通过 CSS 变量引用 token；硬编码颜色 / 阴影 / 圆角 = PR 拒绝合并（见 `prohibition.md` 第 14-15 条）。

#### 7.2.1 颜色 token
| Token | 值 | 用途 |

### 7.3 主题切换机制
- 主题通过 `[data-theme]` 属性切换；组件代码不写死颜色。
- Phase 1 仅一套主题（Warm Claymorphism）。
- Phase 2 预留：`dusk`（夜间暖咖）、`festival`（节日限时主题）。

### 7.4 组件来源治理（多源统一）
- **唯一组件库**：shadcn/ui（通过 token 自动换肤）。
- **引入外部 Figma / 第三方组件**必须先脱色：
  1. 只复用结构（圆角层数、阴影公式、间距比例）。
  2. 色值一律映射到 `--color-*`。
  3. 阴影若与 `--shadow-clay-*` 同构则替换；不同构则新增 token 而非裸写。
- **新增 token** 须 PR + 更新本节表格。

### 7.5 交互原则
- **进度可见但不焦虑**：进度条文案 "已完成 X / 大约 Y 步"，禁用"还剩 N 题"。
- **零强制字段**：所有字段可跳过，默认值合理。
- **错误友好**：错误以"建议"语气呈现，非"错误"语气。
- **撤销随处可达**：所有不可逆操作（删除、生成报告）保留 5 秒撤销窗口。
- **CTA 节制**：每页主 CTA 唯一，次级操作弱化。
- **动效节律**：Framer Motion，过渡 200-400ms `ease-out`；游戏化反馈（完成测评步骤）≤ 600ms 的 spring 弹性。

### 7.6 文案语气
- 第二人称、温和、不催促。
- 禁用感叹号堆砌、紧迫感词汇（"立即"、"限时"、"错过"等）。
- 「想找人聊聊？」入口措辞中立、低压力："如果你想就报告里某条推荐再深入聊聊，可以加我们的 WhatsApp / WeChat。"
- 任何 C 端文案**禁止出现**「中介」「合作机构」「签约」「专属顾问」「免费咨询」等销售导向词。

## 8. 数据模型概要（详见后续 ADR）

### 8.1 核心实体

```
User                  ── Supabase auth.users + public.profiles
StudentProfile        ── 学术背景 + 标化成绩 + 偏好 + 测评结果
AssessmentResult      ── Big Five + 学习偏好 + 生活偏好
Recommendation        ── 单次诊断生成的推荐集合
Program               ── 院校项目（200+ 条，curated）
University            ── 院校（含国家/城市/标签）
ReportCode            ── 6 位报告 ID（C 端称呼）/ 内部团队据此调取方案
AgencyPartner         ── 合作中介（Phase 1 静态，仅 admin 可见）
LLMAuditLog           ── LLM 调用审计
```

### 8.2 关键关系
- `User 1—N StudentProfile`（可多次诊断）
- `StudentProfile 1—1 Recommendation`
- `Recommendation N—N Program`（含分项得分）
- `Program N—1 University`
- `Program N—N Tag`
- `Recommendation 1—1 ReportCode`

## 12. 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| AI 幻觉造成虚假院校信息 | 高 | NFR-5 五重防御 + 审计日志 |
| 院校数据失效 | 中 | 季度复核 + `last_verified_date` |
| 中介后台合作不顺 | 中 | Phase 1 团队人工承接咨询，即使无中介也能保证 C 端体验；先验证模型再 scale |
| 自媒体引流不足 | 中 | 每渠道独立 UTM,数据驱动调整 |
| 隐私合规失误 | 高 | 上线前法律顾问审 PRIVACY/TERMS |
| Vercel/Supabase 免费额度突破 | 低 | 监控告警 + 备选 CF Pages 迁移方案 |
